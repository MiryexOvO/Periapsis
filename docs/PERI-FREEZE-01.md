# PERI 累计卡顿诊断

此工具用于研发验收，测量合成源到软件帧输出；不测物理采集到屏幕。
不改变画质、截止时间、读取预算、编码配置或协议格式。

`pnpm native:live:check`在已有trace旁自动保存`freeze-轮次-模式.json`。
也可以分析旧日志：

```powershell
pnpm native:freeze:check dist/live-check-示例/trace-1-fixed.jsonl dist/freeze-report.json
```

每个播放器进程分别统计两次实际输出之间大于250ms的间隔，冻结估计为间隔减67ms。
报告保存间隔起止帧号、恢复原因、接收/解码阶段最大耗时、解码失败和相关Relay及关键帧事件。
播放器恢复原因包括读取对象放弃、缺少依赖、解码超时/失败、解码确认过期及缓冲触发恢复。
读取空结果不等于已证实网络丢包；可能是对象取消或本地驻留时间耗尽。

缺少播放器恢复证据的间隔明确标记`unattributed`，旧日志不会凭Relay事件推断根因。
`recovery_observed`仅表示间隔内发生恢复，不表示该事件解释了全部停顿。
一次读取或解码可能在间隔开始前就已启动，因此阶段耗时不能直接相加作为冻结分解。
Relay事件仅是共享上下文，多观看者场景不能用其viewer直接对应播放器进程。

阶段耗时来自进程本地单调时钟；跨进程关联使用同机墙钟，只用于受控实验。
统计冻结间隔使用日志墙钟，可能与播放器按单调时钟汇总的数值有毫秒舍入差异；时钟调整时两者不能比较。
没有两次输出包围的启动等待、尾部停顿和程序崩溃不计入本报告，须结合failure.json与首帧/无进展超时检查。
分析程序拒绝输入顺序中的输出墙钟回退；上游已经排序的历史日志不能据此证明原始时钟单调。

高频接收/解码阶段日志由`PERI_PLAYBACK_TRACE=1`启用，默认关闭；研发弱网脚本显式启用。
恢复原因沿用现有低频`PERI_TRACE`事件输出（该前缀不是环境开关）。不记录媒体负载及凭据，新增字段附中文源码说明。

2026-11-05一轮60秒周期中断实验记录16次明显停顿，均有恢复事件相伴，全程14次读取对象放弃、3次缓冲恢复，没有解码失败或超时。
本轮软件延迟P95为339ms、最大输出间隔746ms、单调时钟累计冻结6111ms（8.86%），零重连、解码931帧。
JSONL墙钟分析估计冻结6126ms，15ms差异来自计时/舍入口径；不把墙钟结果冒充原始单调统计。
Relay确认超时与后续依赖丢弃频繁出现，但尚未通过干预对照证明其为全部停顿的根因。
此轮补充观测，没有调整传输策略；不能声明已降低卡顿或得出多轮稳定性结论。

## 对象终结原因与取消修复

新增object_read_end事件：stream为本连接单向流索引；sequence只在完整对象头通过长度/标志校验后填写，否则为null。
phase区分header、payload、fin、selected_out及complete；reason区分residence_timeout、peer_reset_1、selected_out、read_error及cancelled。
完整成功对象不额外输出此事件。严格读取仍把重置/截断作为错误；实时/恢复读取才将明确RESET(1)视为正常缺口。
retained_slot_expired单独标记保留槽到期，completed指出其负载是否已经完整，避免将跨调用缓存到期误认为网络超时。
取消future只证明本地停止读取，不证明上游丢包；保留窗口被替换、清空和调用取消均可能触发它。

新增object_send_cancel事件记录对象序号、流索引及写入期限、确认期限、对端停止或等待中断等原因。
freeze报告的objectFailures按原因汇总，并保存同序号/流号、不同进程且一秒内先发生的发送取消候选。
这只是关联线索：流索引在不同连接内会重复，尚未建立跨进程连接身份映射，不可据此断言因果或多观看者归属；未知序号不参与候选匹配。
间隔内readEnds和sendCancels保留具体证据，header阶段无序号的放弃不强行映射到某一媒体帧。

串行严格/实时/恢复接口已复用流保护器，外层future取消时显式STOP(1)。
回归测试证明旧裸流路径会发送默认STOP(0)，修复后统一使用局部放弃码1且下一对象仍可正确接收。
此修复没有改变默认接收策略、读取预算、码率、源画质或线协议版本，也未证明它是此前累计冻结的唯一根因。

2026-11-06默认串行模式一轮60秒周期中断实验：931帧、零重连，软件延迟P95为373ms、最大392ms，最大输出间隔542ms，冻结3265ms（4.97%）。
全程记录8次payload阶段本地驻留超时、2次header阶段RESET(1)和32次主动跳过依赖对象；9次明显停顿均观察到恢复事件。
8次停顿伴随本地负载读取超时，剩余1次伴随头部阶段RESET(1)；这将下一轮重点指向负载未能在期限内收齐，而非把所有取消合并归因为发送ACK。
发送侧另有31次确认期限取消和3次对端停止，不能与接收事件按数量直接一一对应。
单轮诊断没有证明取消修复降低了冻结，不能替代多轮对照或物理端到端测量。

# PERI 当前模块与第三方接入边界

项目已经初步分层，但尚未形成稳定发布的第三方 SDK。工作区当前有六个 Rust crate，默认核心成员为四个，另有 peri-obs 与 peri-webtransport 接入组件；
原生协议的大部分能力仍以 `peri-native` 内部模块提供，并非每个模块都独立成包。
表中的“已有”描述当前实现，不代表标准化、生产就绪或独立实现互通。

## 给外部开发者保留的路径

外部采集/编码器 → 公共 Rust Publisher → PERI 会话/对象 → Relay 或原生接收端。
接收端也可使用公共 Subscriber，将编码数据交给自己的解码器和渲染器。
协议不要求接入方使用测试画面、Python、FFmpeg、我们的播放器或码率策略。

Rust 库当前可以通过本地 path 或固定 Git 提交集成；所有 crate 均为 0.1.0、publish=false，
尚未发布到 crates.io，也没有稳定 SDK/API 兼容承诺。
身份、证书信任及 QUIC Endpoint 配置由接入应用负责；协议库提供鉴权会话和媒体 API。

其他语言可按公开实验线格式开发独立实现。目前已有 OBS 专用 Rust C ABI 和 Windows C++ 插件，以及 WebTransport 浏览器网关；尚无通用稳定 C++ SDK 或独立实现互通证明。接入与部署见[节目音视频接入](PERI-PROGRAM-AV.md)。现有 Rust/TypeScript 互通实验不等于新原生线协议跨语言互通。

## 尚未完成的模块边界

- 独立传输适配接口和易用 Endpoint/Client Builder，避免接入方直接处理全部 Quinn/TLS 配置。
- 核心媒体协议、策略、服务和工具的 crate/feature 进一步拆分；当前 module 不等于可单独安装的软件包。
- 通用调度原型与原生 DecodeBuffer 的职责统一，避免两套调度逻辑演进分叉。
- 可协商的扩展执行机制、版本演进规则与一致性测试向量。当前不能把扩展能力字段视为已实现插件系统。
- 通用稳定 C ABI / SDK 发布，以及原生音频播放同步；现有 OBS 专用 C ABI 和浏览器网关仍需产品化验证。
- MPQUIC/P2P 当前为研发方向，没有已实现的可启用模块。

第三方 Rust 接入步骤见[接入指南](PERI-INTEGRATION-01.md)，线格式见[协议草案](PERI-WIRE-02.md)。

## 依赖边界

正式Cargo工作区包含六个crate，默认成员为四个核心crate；默认构建与全工作区构建均不包含内部对照实现。
内部研发工具独立管理依赖和锁文件，不作为第三方接入模块或对外SDK能力。
协商状态机接收中性的传输就绪通知；具体传输认证、ALPN和版本检查由连接层负责。

## 当前约束

Session负责会话、角色和连接所有权；send.rs负责对象写入及传输确认，receive.rs负责读取和取消。
普通对象与修复片共用发送执行器和Deadline，修复适配器只安排分片工作，不另写一套QUIC发送逻辑。
发送句柄用一个状态表示写入、等待确认和终结；接收终结原因也使用枚举，日志字段沿用现有格式。
零预算不得打开对象流，过期句柄即使已有ACK也返回Timeout；期限溢出返回错误，不触发panic。
保留接收槽与读取future共用同一个驻留期限；修复组的150ms重组上限仍单独约束完整对象恢复。

这一步尚未统一全部接收策略，也未建立覆盖Relay、重组和解码的连接级内存预算。
后续改动先定义责任边界和失败处理，再接入现有链路；新抽象应替代重复实现，避免长期并存两套执行逻辑。
源码注释使用中英双语，解释所有权、期限、协议约束和取舍；不重复代码表面行为，不使用架构等级或性能宣传词。
运行结论须说明配置与测量范围；失败结果保留，测试通过不等于弱网性能达标。

## Relay 的执行与配额边界

每个观看者的媒体操作分为排队、待写入、待确认三个阶段。最多一个待写入操作；待写入与待确认合计最多四个。
控制反馈、写入进度和发送确认在同一事件循环中推进；反馈不重建待写入future，不刷新对象期限。
每轮最多处理八条恢复反馈，select采用公平轮询，避免反馈持续到达时饿死写入与确认。
Relay入队时刻加协商驻留时间形成绝对期限，直接传入Publisher和修复适配器，直到ObjectSend确认结束。
等待写入期间若前驱失败，会在保留发送句柄前重新检查依赖并触发恢复。

Limits.buffered_bytes按观看者限制三个阶段保留的Frame.payload字节，默认12×(1MiB−68)。
每个队列项持有独立额度句柄，移动到待写入和待确认阶段时继续持有；确认、失败或任务取消时释放。
共享Arc负载按观看者分别计费，是保守的连接负载额度，不是进程真实内存统计。
接收器缓存、媒体元数据、封装副本、修复分片和Quinn窗口另外有上限，尚未纳入同一总预算。
单观看者达到帧数或字节上限时取消该观看者；其他观看者继续接收。两个限制取先到者。
所有观看者的最大负载预留按min((queued_frames+4)×frame_bytes,buffered_bytes)×viewers计算，不能超过128MiB。

真实QUIC回归将观看者单流窗口限制为4096字节，暂停读取256KiB帧，并验证恢复反馈150ms内到达源端。
恢复旧的阻塞等待实现会使该测试超时；重构实现通过。这证明反馈不再等待媒体写入结束，不等于弱网冻结已经下降。

# PERI 常驻编码与合并切换实验

这一实验减少单观看端调节过程中的编码器重建，保留原策略作为对照。
默认仍为固定码率；以下两个开关共同启用候选方案：

```powershell
$env:PERI_ADAPTIVE = '1'
$env:PERI_SWITCH_POLICY = 'coalesced'
```

使用方法沿用[实时编码源](PERI-LIVE-01.md)。`PERI_SWITCH_POLICY=legacy` 使用原重建策略。
实验接口需要 Python/PyAV 16.1.0 与可用的 libaom AV1 编码器。

## 编码器与切换

当前固定编码构建在运行中只赋值 `bit_rate` 并不会改变输出；不能据此宣称热更新有效。
对应 [FFmpeg n8.0 编码器源码](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n8.0/libavcodec/libaomenc.c)也没有运行时重配置入口。
本实验没有修改或升级底层编码库。

候选方案保持四个编码上下文：100、150、225、300 kb/s。
它们持续编码相同的原始帧，各自保留参考和码率控制历史；每帧只发布选中档位的一个包。
切换到另一档时，目标编码器生成独立关键帧，随后沿用该上下文的参考链。
不会发送该档位此前未发布的依赖帧，也不会通过跳过原始内容切换。
固定模式与 legacy 模式仍使用一个上下文。

原控制器给出的目标向下映射到固定档位。待应用目标可以反复覆盖，只保留最新值：

- 码率变化本身不立即制造关键帧。
- 优先与允许的恢复关键帧合并；否则在距离实际上一关键帧至少 60 帧的时机应用。
- 相邻档位切换至少间隔 45 帧，避免短期反复切换。
- 所有显式强制独立帧共用至少 15 帧的间隔；自然关键帧不计入该强制预算。

自然关键帧时机是按当前受限配置预测，并非通用编码器协议保证。
实际是否为关键帧仍检查编码输出，缺少独立性即失败退出。
此方案不会实现精确的线上峰值速率上限；关键帧依然可能超过瞬时网络预算。

## 资源代价

候选方案最多保持四个常驻编码上下文并执行四次编码，增加处理时间和编码器内部内存。
这是固定 320×180、15 fps、单线程编码上下文的实验，不代表高分辨率、多路或硬件编码性能。
进程退出时释放上下文；不按任意网络输入创建无限数量的编码器。
调节仍仅限单观看端实验，尚无多观看端目标聚合。

`PERI_ENCODED` 增加第四列处理微秒数；包括原始帧构造、工作进程 IPC 与所有上下文编码，
不是单个编码器耗时或 CPU 利用率。
`PERI_RATE_SWITCH` 记录实际档位变化；恢复响应和纯码率切换分别记录，避免把两者重复计数。

## 验证

```powershell
pnpm run native:live:check
```

先验证 90 帧四次跨档切换均能实际解码，再比较 fixed、legacy、coalesced 三组。
默认三轮循环轮换组别顺序，所有组使用相同合成内容、播放器和 UDP 扰动配置。
每次重启发布源，播放 60 帧，并检查实际丢包、零重连和接收报告。

报告增加实际档位变化次数、平均编码处理微秒与 P95。
恢复日志和离线 PSNR 沿用[反馈调节实验](PERI-ADAPTATION-01.md)。
离线 PSNR 是固定目标单上下文参考，尚不是所有网络展示帧的混合档位画质评估。
候选方案同时改变目标档位集合、切换时机和编码器生命周期，三组实验不能单独归因每个因素。
固定码率是否更好仍需同时看冻结、流量和画质；实验开关不代表推荐生产配置。

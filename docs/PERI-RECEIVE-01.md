# PERI 四路恢复接收候选

状态：实验能力，CLI默认关闭。只改变本地恢复接收调度，控制协议和对象格式保持02。

## 接入

`Session::recv_recovery_concurrent(total_budget, residence)`与媒体层同名接口可在所有依赖轨道都处于恢复时使用。
此接口交付首个读取完整且带FIN的独立对象；其他已接受流统一STOP(1)。
不保证流序号或媒体序号顺序，不挑选最新关键帧，也不代表解码成功。
混合音视频或仍有正常播放轨道时不能直接使用此策略，以免取消仍需保留的媒体。
正常播放接口及原有串行恢复接口不变；CLI候选目前用于单视频AV1实验。

```powershell
$env:PERI_RECOVERY_CONCURRENCY='4'
pnpm native:live:check
```

环境值仅允许1或4，默认1。弱网报告记录recoveryConcurrency以便区分实验。

## 资源与取消

- 同时最多接受四条对象流，每条在分配前校验1MiB负载上限，应用读取负载总上限4MiB；不包含QUIC接收窗口、媒体解析或解码器内存。
- 没有后台读取任务、隐藏完成队列或跨调用积压；返回、报错及外层取消都会同步释放读取future并对未完成流调用STOP(1)。
- 每条流的驻留预算从接受时算起，范围大于0且不超过1秒；total_budget为整次调用总预算，不因跳过对象而重置。
- 超出总预算返回Timeout。驻留超时、明确RESET(1)或合法依赖对象跳过可导致None；若仍有其他读取在途，继续等待其结果。
- 非法头部、截断、额外数据及其他reset码仍返回错误；完整负载没有FIN时不交付。

四槽都被慢流占用时，后续流须等待槽释放；本能力并未消除所有阻塞。
取得一个独立帧时取消其他已接受流也可能丢掉较新的有用帧，并触发发送端恢复反馈，需结合弱网长测判断收益。
正常播放仍串行，尚未实现持续乱序接收、依赖重排与解码调度的完整流水线。

## 验证

真实QUIC测试覆盖三条停在头部的旧流被第四条完整关键帧绕过、四槽满时第五条不被读取、总超时/外层取消STOP(1)及后续正常接收。
同时覆盖长度越界、截断、无FIN、显式RESET(1)、其他重置码和驻留超时。
这些是功能与边界验证，不构成整体画质、时延或累计卡顿改善的证明。

2026-11-06各一轮60秒周期中断诊断对照（四路后串行，配方相同），均931帧、零重连，满足当前软件亚秒判据：

| 指标 | 串行 | 四路候选 |
| --- | ---: | ---: |
| 软件延迟P95 | 312ms | 389ms |
| 最大输出间隔 | 468ms | 557ms |
| 累计冻结比例 | 5.97% | 10.84% |

本次四路样本表现更差，保持默认关闭。各仅一个样本，不据此认定唯一根因；下一步需验证保留较新在途帧与依赖重排的方案，避免过早取消有用对象。
后续新增的[四槽有序保留候选](PERI-RETAINED-01.md)单独使用PERI_RECEIVE_RETAIN开关，原四路取消策略保留以供内部对照。
这些为同机合成源到软件输出指标，尚未证明物理采集到屏幕时延或长期真实网络表现。

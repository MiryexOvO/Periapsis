# PERI 原生实验线协议 02

状态：实验原型，允许不兼容变更。当前仅实现单资源、单向发布订阅，未定义正式稳定版本。
实现为 `crates/peri-native`，直接使用 QUIC，不依赖早期第三方对象传输模块。

## 连接与安全

使用 QUIC/TLS，实验 ALPN 为 `peri-dev-02`。双方必须验证 TLS 协商出的 ALPN。
不提供其他应用协议回退，也不将字符串替换视为协议兼容。
调用方负责服务器证书信任、客户端身份、资源访问授权、连接数、QUIC 流和接收窗口配额。
订阅资源匹配不等于身份认证。受保护接入与原生服务见 [分进程服务](PERI-SERVICE-01.md)。
尚未完成互联网运行验证。

一个连接只服务一个资源。调用方交付连接后必须独占使用，Session 释放关闭连接。
当前不支持 0-RTT 应用数据、会话续接或浏览器 WebTransport。
主动发布及 Relay 的新增行为见 [发布与分发实验](PERI-RELAY-01.md)。

## 控制流

订阅端发起一个双向流，先写入 8 字节前导：

```text
50 45 52 49 00 02 00 00
 P  E  R  I  version reserved
```

版本为大端 u16 的 2，保留字段必须为零。当前只能精确匹配版本，不进行降级。
后续每条控制消息使用大端 u32 字节长度，再跟 UTF-8 JSON；长度必须为 1–16,384。
接收方在分配消息内存之前校验长度。控制封装的未知字段与未知消息类型拒绝处理。

按以下顺序交换：

| 方向 | type | 额外字段 |
| --- | --- | --- |
| 订阅端 → 发布端 | `peri.subscribe` | `resource`、`hello` |
| 发布端 → 订阅端 | `peri.accept` | `hello`、`agreement` |
| 订阅端 → 发布端 | `peri.ack` | 无 |

主动发布模式以 `peri.publish` 替代首条 `peri.subscribe`，字段相同；
接入端应答配置并等待发布者 ACK，之后由主动发布端发送单向对象流。
调用方必须选择匹配的接入 API，不能让订阅请求获得发布角色。

受保护发起端在subscribe/publish消息中增加可选authorization字段，为32–128字节ASCII可见字符的原始凭据，未提供时省略。
accept_authenticated先按角色校验凭据、匹配资源才发送接受消息；失败关闭，不回退未鉴权接口。
发布与订阅凭据必须独立且不同；字段经当前TLS控制流传递，不支持0-RTT，不是恢复令牌。
早期严格实现可能拒绝新增字段，不宣称受保护模式与这些实现兼容。

资源长度为 1–256 ASCII 字节，允许字母、数字及 `/ _ - .`，按原始字符串精确匹配。
资源是逻辑标识，不是文件系统路径。

`hello` 复用共用类型：`version`、有序 `profiles`、`codecs`、`extensions`。
当前版本为 1；配置为 `interactive`、`live`、`quality`，编码是协商字符串。
配置、编码和扩展各最多 32 项；编码字符串长度上限 128。能力校验由 peri-session 执行。
`agreement` 包含版本、选中配置、共同编码、扩展、`targetBufferMs` 和 `maxBufferMs`。
发布端按本地偏好选择；订阅端重算并逐字段比较，匹配后才能发送 ACK。
这些嵌套结构没有额外的 `type` 字段。发布端收到 ACK 后才开放发送 API。
连接本身关联会话，当前不定义跨连接 sessionId。

一次协商使用调用方提供的总时间预算。错误、超时或协商 future 取消都会关闭连接。
控制流随 Session 保留；激活后允许接收方发送 `{"type":"peri.keyframe","track":1,"origin":1234,"id":1,"viewer":0,"after_sequence":42}`。
仅媒体接收角色可请求，track 必须为目录内的视频轨道。请求不表示已生成、已收到或已解码。
发送端合并 200 ms 内的请求；接收侧每秒最多接受 10 条，队列上限 8，满时丢弃请求。
非法角色、零轨道、未知消息或超频会关闭连接；媒体层轮询时拒绝未知/音频轨道。
后台读取任务随 Session 释放而取消；控制写入限 200 ms，失败或中途取消关闭连接，避免复用半条消息。
没有新增控制流或对象头，旧实现未必支持激活后反馈，本阶段不承诺向后兼容。
暂不实现反馈确认、关键帧响应时限、保活或结构化拒绝消息。

## 对象流

每个对象使用一个发布端发起的独立 QUIC 单向流，全部整数为大端：

| 偏移 | 字段 | 长度 |
| --- | --- | --- |
| 0 | sequence | u64 |
| 8 | timestamp_us | u64 |
| 16 | duration_us | u32 |
| 20 | flags | u8，bit 0 表示独立解码单元，其他位必须为零 |
| 21 | payload_length | u32，1–1,048,576 |
| 25 | payload | 指定长度的编码数据 |

有效对象必须收到完整 payload 和流 FIN，额外字节、截断、保留位或非法长度均拒绝。
时间戳属于发布端媒体时间轴，不是跨机器同步时钟；不能据此直接测单向延迟。
基础对象层不解释轨道、媒体目录、依赖或多轨同步。可选的
[media-01 负载配置](PERI-MEDIA-01.md) 定义目录、初始化数据与依赖。
序号用于应用层识别，不保证流间交付顺序；基础对象 API 不自动去重或恢复依赖。

SDK 允许并发发送，活动发送上限为 8；预算覆盖等待名额、开流、写入和传输确认。
`start_send` 按调用顺序开流并写完对象，返回持有名额的 `ObjectSend`；
调用方须及时调用 `finish` 等待传输确认，或丢弃以取消该对象。
保留句柄而不驱动 `finish` 不会自动执行截止时间取消，但始终占用有界名额。
`send` 等价于排队后立即等待 `finish`；两者都不代表解码成功。

发送超时或取消会复位未完成对象流。发送成功只代表传输确认，不代表观众解码或播放。
`recv` 每次收取一个对象，预算包含等待新流、读取头部、payload 和 FIN。
接收失败或取消会停止该流，可继续收取其他对象；不自动恢复被取消对象的依赖。
实时调用方可使用 `recv_live(idle, residence)`：等待新流与已接受对象的驻留预算分开，
驻留预算须大于零且不超过一秒。对象读超时发送 STOP_SENDING(1) 并返回 None；
收到明确的 RESET_STREAM(1) 同样返回 None，表示当前对象放弃，应用须处理依赖缺口。
发送端超时或取消使用 RESET_STREAM(1)，收到 STOP_SENDING(1) 映射为 ObjectAborted。
其他 reset 码、非法长度、额外字节及无显式 reset 的截断仍返回错误，不能当成正常过期。
目录和握手仍使用严格 API；没有改变对象字节格式，也不保证旧客户端能容忍这些取消。
常规接收与原有恢复接口仍串行；实时 API 为每条已接受的慢流设上限。
另有仅在全轨道恢复时使用的[四路恢复接收候选](PERI-RECEIVE-01.md)，不提供正常播放的持续乱序接收调度。

## 可选增强与研发边界

MPQUIC 的定位确定为可选原生端多路径增强模块，单路径须完整可用。
当前 QUIC 接入没有实现多路径；本地能力仅可提供已实现的peri.repair版本1，其他未实现扩展仍拒绝。
默认CLI能力列表仍为空；[修复内核](PERI-REPAIR-01.md)需要专用适配器，尚未接入正式Relay播放。
未知可选远端扩展省略，未知必选远端扩展导致协商失败。
未来扩展必须由传输栈实际能力、双方协商和运行时策略共同启用。
浏览器不承担多网卡控制要求；多路径不等于 P2P。

基础对象层的时间预算属于本地 I/O 取消机制，不是端到端播放截止时间协议。
media-01 另提供接收端本地依赖/截止时间缓冲，需要调用方提供播放时间映射和解码确认。
已有单资源 Relay 库、分进程命令、角色凭据、AV1 示例、接收反馈与可选码率实验；稳定 SDK、
推流软件 SDK/插件、P2P 和多路径调度尚未完成。
本原型不声明标准符合性、独立实现互通或相对其他协议的性能优势。

新增恢复请求关联字段与接收状态报告见[反馈调节实验](PERI-ADAPTATION-01.md)。

## 02 恢复定位与迁移

02使用ALPN peri-dev-02与前缀PERI\x00\x02\x00\x00，不能与01端点混用，双方须同步升级。
媒体对象包格式与Hello能力版本保持不变，本次变更为控制协议版本。
恢复请求的viewer由Relay重写为本次资源内订阅者ID，与ReceiverReport.viewer保持一致。
after_sequence由播放器填写最后正常输出序号，Relay自身发起时填写故障对象序号；0表示未知。
没有新鲜、同轨道、同订阅者且sequence严格更大的有效报告时，不得认定此请求已经过时。
这些字段用于恢复判断和追踪，不是身份凭据；访问授权仍由会话层负责。

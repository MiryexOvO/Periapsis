# PERI 有界对象修复内核 01

状态：已实现修复内核和媒体层有界适配器，可选接入正式Relay和播放器。
默认CLI仍关闭；设置PERI_REPAIR=1才在Hello提供可选能力，双方接受后启用。
接通与对象还原不代表弱网冻结改善；性能结果与限制见文末。

## 能力与接入边界

专用适配器在Hello加入repair::capability(false)，表示可选的peri.repair版本1。
只有实际会话Agreement接受此能力后，Codec::new才能创建编码器/重组配置。
对端不支持可选能力时共同扩展为空，继续原始对象传输；必选能力不匹配时握手失败。
本地能力校验仅新增允许peri.repair版本1，其他未实现能力仍拒绝，不代表启用了多路径。
PERI ALPN与前导保持02；修复片是协商后的可选对象负载，不改变基础对象头。

公开接口位于peri_native::repair：

| 接口                               | 职责                                         |
| ---------------------------------- | -------------------------------------------- |
| capability / Codec::new            | 提供能力、检查真实协商结果                   |
| Codec::split                       | 完整对象包拆成数据片及一片异或校验           |
| Codec::protect / RepairBudget      | 检查额外字节预算，不足时返回None             |
| Fragment::encode / decode          | 有界分片序列化及严格校验                     |
| Fragment::to_object / from_object  | 专用适配器通过原生对象流承载                 |
| Codec::assembler / Assembler::push | 按组重组、校验、返回完整原对象               |
| Assembler::expire                  | 显式驱动过期释放，迟到片不能重新开启已结束组 |

调用方必须按资源、发布生命周期和已认证连接隔离Assembler，不能跨会话复用组号历史。
协商成功时media::Publisher/Subscriber自动使用内部repair/transport.rs适配器，Relay和共享播放器复用此路径。
原始Session.send/start_send/recv仍处理原始对象，适用于自建适配器与协议夹具，不自动重组。
不能把单个修复片交给Frame::from_object；必须通过完整性校验后的重组对象。

## 分片格式

编码输入为完整原生对象包，包含原来的25字节对象头。原对象sequence和duration_us必须大于零；目录等序号0对象走原始路径。
每组2至32个数据片，加1个异或校验片。片负载64至1024字节，最后一个数据片补零。
完整原包最多32768字节（原payload最多32743字节）；过小/过大或不能满足片数约束时split返回错误，适配器需明确选择原对象路径。
这不是无限长度文件分片，也不保证一片恰好对应一个UDP数据报。

| 偏移 | 字段                                             | 字节 |
| ---- | ------------------------------------------------ | ---: |
| 0    | 魔数PRPR及版本/保留字节：50 52 50 52 01 00 00 00 |    8 |
| 8    | 原对象序号/组号，大端u64                         |    8 |
| 16   | 原生对象包总长度，大端u32                        |    4 |
| 20   | 数据片数n                                        |    1 |
| 21   | 片号0至n，n表示校验片                            |    1 |
| 22   | 补齐后的片负载长度，大端u16                      |    2 |
| 24   | 原生对象包SHA-256                                |   32 |
| 56   | 定长数据或校验负载                               | 片长 |

解码先检查固定头、魔数、原包长、片数、片号、片长和总长度，再复制负载；不接受尾随字节。
用Object承载时，外层wire_sequence独立编号，timestamp_us和duration_us为0，independent必须为false：单个修复片不是可解码帧。
协商后的配置将上述零时长/非独立信封保留给修复片；正常媒体单元时长为正，序号0目录仍按原规则处理，适配器据此分派两条读取路径，不能只猜负载前缀。
重组后恢复原对象的序号、时间戳、时长和独立标志，并再次执行共用对象封装校验。

## 恢复与完整性

校验片为所有补齐数据片的逐字节异或。任意一个数据片缺失时，用校验片异或其余数据片补回。
全部数据片齐全时不需要校验片；缺失两片数据时不能恢复，保持等待直到过期。
这处理的是已知丢片，不是任意错误纠正。重组后必须通过SHA-256、原对象头和组号一致性校验才交付。
哈希不代替TLS认证或角色鉴权。损坏重组失败后结束该组，不能把半帧或校验失败结果交给解码器。
Complete.repaired只表示补回过一个数据片，不表示已经解码或显示。

## 资源、期限与预算

默认最多4组，缓存负载预留上限128KiB，组寿命150ms；可配置最多8组、256KiB，寿命不能超过协商maxBufferMs且至多1秒。
Interactive协商上限100ms时应显式设置不超过100ms的组寿命，不能直接沿用150ms默认值。
每组首次接纳就预留所有数据片及校验片的负载空间；读取输入、少量元数据和至多约64KiB重组/解析临时数据另计，不将缓存额定值当成进程总内存。
组满或字节不足返回AtCapacity，不驱逐既有有效组；重放历史上限128项，过旧组号直接Stale。
第一次接纳时的截止时间取调用方deadline与本地max_age较早者；重复及后续片不刷新期限。
同组元数据冲突、同片号不同内容返回错误且不覆盖已有有效片。完全相同的重复片返回Duplicate。
没有后台计时器，调用者应及时驱动expire；push也会先清理过期组。

RepairBudget使用单调时间令牌桶，速率和突发额度均显式配置、上限65536字节；时间回退不增加额度。
收费为整组相对原对象新增的全部原生字节，包括校验、补齐、所有分片56字节头和每条外层对象25字节头。
不包含QUIC/TLS/UDP/IP开销，接入方还需留出传输预算；不能仅按校验负载大小估计总带宽增加。
protect预算不足返回None，调用方发送原始对象；底层split不自带限流，仅适用于自行管理额度的适配器。

## 验证范围

测试覆盖任意单数据片丢失、校验片丢失、最大32片、两数据片丢失、重复/冲突/损坏、长度越界、缓存容量、重放、原始期限和令牌预算。
真实QUIC夹具在已协商的直接会话上逐次省略4个数据片或校验片，5种情况均在150ms本地预算内还原原始对象，迟到片不重复交付。
这是应用层片省略夹具，没有模拟真实UDP随机丢包、慢片重传或正式Relay播放，也不是网络端到端性能证明。
可选协商回退、必选不匹配拒绝已在真实QUIC上验证；默认媒体链路另行回归。

## 媒体适配器与运行边界

发送端每连接一个媒体对象句柄，组内最多四个分片future，仍受Session八个底层发送槽约束。
取得对象槽后才复制媒体负载；单组最多33片、原包32KiB，句柄释放同步取消在途future。
受保护组一直持有对象槽直到全部分片确认。原始对象按序写入后释放对象槽，其确认继续占用底层Session槽。
发送deadline从start调用起算，包含槽等待、全部写入和确认；不会按分片刷新。
额外原生字节预算固定8192字节/秒、突发4096字节；不含QUIC及UDP开销，不等于总流量上限。
非独立原包1025至3072字节使用1024字节分片，最多三个数据片加一个校验片。独立帧、目录、其他尺寸及超出冗余额度的对象走原始流。
不支持扩展的对端继续完整原始媒体路径，双方能力必须逐跳协商，不能把上游结果套用到下游。

接收端最多四个读取future，每流按原始对象读取器的1MiB负载上限分配；此约4MiB额度在128KiB重组缓存之外。
重组最多四组，寿命min(150ms,协商maxBufferMs)，再受首个被接受分片流的驻留deadline约束。
后续分片、重复片和跨调用保留均不延长期限；重组计时器在无新流时仍驱动过期。
无后台收片任务、无额外无界完成队列。总调用超时、错误或取消时STOP(1)全部已接受流，并终结已知组且保留重放历史。
成功返回保留其他在途流；显式clear_retained_receive也清理修复状态。

协商修复后，Subscriber所有收帧方法使用同一个四槽重组器；恢复过滤在还原完整对象后判断independent。
它不能按修复片外层头跳过依赖帧，且不叠加原有串行/四路/retained候选算法，不能把这种对照解释为纯FEC收益。
recv_retained在此模式下也不提供原始retained算法的开流顺序保证；目前依靠发送端组间顺序保留媒体顺序。
原始Session接收接口和未协商修复的Subscriber行为保持原规则。

repair_send、repair_fallback、repair_complete、repair_expired记录策略观测；repaired=true只说明用过校验片，
可能由应用读取顺序触发，不能据此推断发生过真实UDP丢包、缩短了重传等待或已经显示画面。
network-report中的repairCounters聚合双方进程和两跳，不能当成下游独立恢复率。

设置PERI_NETWORK_PROFILE=burst、PERI_NETWORK_MODES=fixed、PERI_NETWORK_REPEATS=1、PERI_REQUIRE_SUBSECOND=1，
分别以PERI_REPAIR=0与1运行pnpm native:live:check。保存失败报告，不调宽截止时间或降低源画质以通过验收。
这是同机合成编码到软件输出的受控实验，不能代表物理采集到屏幕，也不能用单轮结果作稳定性能承诺。

同一burst配方，固定码率、原始关键帧配置、默认ACK/接收预算，双方均使用同一套PyAV和FFmpeg 8.1.2。

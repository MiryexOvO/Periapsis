# PERI 1.0 协议发布规范

首版发布日期待发布者确认。实现版本 1.0.0；协议版本 1.0。本文件定义稳定范围与兼容政策。

## 稳定范围

PERI 在 QUIC/TLS 上提供单连接单资源的单向发布或订阅，Relay 将发布者媒体分发给订阅者。浏览器通过网关接入；浏览器 WebTransport/HTTP 封装不等于原生线协议。

1. 连接与控制封装、角色握手、鉴权、对象流和取消语义：见 [WIRE-02](PERI-WIRE-02.md)。
2. 目录、媒体帧、轨道与依赖关系：见 [MEDIA-01](PERI-MEDIA-01.md)。
3. 恢复请求和接收报告字段：见 [ADAPTATION-01](PERI-ADAPTATION-01.md)。其中编码器调节算法、环境变量及实验结果不是互通要求。
4. 稳定产品配置为 AV1 视频与 Opus 音频；使用原有目录初始化数据布局。其他编码字符串可以协商，但不因此获得解码互通承诺。

以上文档中“实验”描述保留研发历史；1.0 冻结的是已实现的报文、校验规则和角色语义，不冻结本地队列大小、调度、编码策略或性能数值。与本文件范围冲突时以本文件为准。修复扩展 peri.repair、四路接收候选、多路径、P2P、自动分辨率降级不属于 1.0 必需能力。默认关闭的实验不得被部署脚本自动开启。

## 三种版本不可混淆

| 标识 | 1.0 的值 | 含义 |
| --- | --- | --- |
| 发布版本 | 1.0.0 | 服务端与配套 OBS 构建版本 |
| 协议版本 | 1.0 | 本稳定规范 |
| ALPN | `peri-dev-02` | 历史标识原样保留，不表示允许任意变更 |
| 控制前导 | `50 45 52 49 00 02 00 00` | 线封装 revision 2 |
| Hello.version | 1 | 能力协商版本 |
| 推流码前缀 | `peri1_` | 地址无关的凭据封装版本 |

不可因字符串包含 dev 而自行改为其他 ALPN。没有注册标准、MoQT/WebRTC 互通或独立第三方实现互通认证的声明。

## 兼容规则

1.x 修订不得改变既有字段含义、前导、长度上限、角色授权或取消语义。控制封装当前严格拒绝未知字段，不能直接增加 JSON 字段并宣称向后兼容；新能力必须在可协商扩展中定义，或以新主版本及独立 ALPN 隔离。未知必选扩展必须拒绝，不允许静默降级身份校验。

补丁版修复实现缺陷并保持线协议和配置兼容。1.x 功能版只允许兼容增强。任何破坏互通的修改须发布协议新主版本，保留迁移文档。Rust API、OBS 专用 C ABI 和浏览器内部接口尚不是独立稳定 SDK；OBS 两个 DLL 必须成套更新。

近期实验版使用同一 ALPN，但实验期间曾修改反馈与鉴权细节，不能保证所有 0.1 构建互通。首次正式部署应成套更新发布端、Relay 和网关。

## 安全与运行边界

QUIC 使用 TLS；新推流码包含证书 SHA-256 指纹、发布凭据、服务器名称和资源。指纹精确匹配是主播端信任锚，不能跳过校验；它不是 WebPKI 域名或有效期验证。推流码须经可信渠道传递；更换证书或发布凭据后需重新分发。地址采用 `peri://IP:端口`，IPv6 加方括号；域名尚不支持。

发布/订阅权限分离，不接受 0-RTT 应用数据。对象取消不代表整条连接失败；发送确认不代表观众已解码。接收方需执行媒体依赖验证和恢复。时间戳属于媒体时间轴，不是跨主机单向延迟测量值。

本版不保证任意弱网下维持原画、零冻结或固定延迟，不包含多租户管理、观看者账户权限、CDN 和高可用控制面。HTTP 兼容观看不提供 HTTPS 页面传输保护；原生 QUIC 的 TLS 与网页 HTTPS 是两个独立层面。

## 发布验证

固定报文样例见 `tests/fixtures/peri-1.0.json`，Rust 实现回归验证与独立 JavaScript 封装解析共同检查字节契约。这只覆盖封装一致性，不替代完整第三方互通测试。发布要求见 [发布操作](RELEASING.md)，升级与回滚见 [1.0.0 说明](RELEASE-1.0.0.md)。

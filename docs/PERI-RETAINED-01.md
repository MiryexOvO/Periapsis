# PERI 四槽有序保留接收候选

此候选在原四路恢复读取基础上保留胜出关键帧之后的对象，默认关闭，线协议不变。
只面向单资源按递增媒体序号开流的发布者及所有依赖轨道一起恢复的场景。
播放器目前仅将其用于单视频AV1；混合音视频需要另行设计轨道调度。

```powershell
$env:PERI_RECOVERY_CONCURRENCY='4'
$env:PERI_RECEIVE_RETAIN='1'
pnpm native:live:check
```

`Session::recv_retained(total, residence, recovering)`和`Subscriber`同名接口必须配套用于恢复和正常接收。
恢复模式选择首个完整独立对象，只取消其之前的流，保留之后已经完成或尚未完成的对象。
正常模式按开流顺序交付，后续帧即使先完成，也不能越过仍未完成的前序对象。
交付对象序号必须严格递增；不符合发布约定时返回协议错误。
本接口不按任意媒体依赖图拓扑排序，也不把接收成功当作解码或显示确认。

## 边界与生命周期

读取中和已完成待交付对象共用四个槽，内部负载分配总上限4MiB，另须配置QUIC接收窗口及应用解码缓存。
保留期间不创建后台任务；调用方应及时驱动接收。驻留期限在接受流时确定，跨调用及解码等待都不刷新。
完成但过期的对象同样丢弃。没有后台计时器在应用停止驱动时自动清理，不过窗口仍保持四槽上限。
单次调用总预算不因到达或跳过对象而重置；超时、读取错误或调用future取消时清空窗口并STOP(1)未完成流。
成功返回后可以留有至多三个后续槽；后续调用继续使用它们的原始期限，不能用新的residence延长。
四槽满时不接受第五条，正常模式仍可能等待最早对象的期限；本候选没有消除全部顺序阻塞。

窗口非空时调用旧接收API会返回pending retained receive，以避免两条接收路径抢流。
需要切换时显式调用clear_retained_receive停止窗口；清空不重置已交付序号。
发送控制反馈不受这个切换限制；角色授权、对象头、FIN及错误校验保持原规则。

## 验证

真实QUIC交错测试：旧流停住，关键帧只到一部分，后续参考帧先完整到达、再后一个参考帧部分到达。
关键帧补齐后，旧流被STOP(1)，两个后继对象仍可原样按序交付；旧接收API不能绕过非空窗口。
另覆盖完整/部分保留对象到期不续命、外层取消后STOP(1)清理及模式显式清空。
功能验证不等于稳定性能提升；默认保持串行，需要结合累计冻结和软件延迟判断实验结果。

2026-11-06保留模式一轮60秒周期中断实验：931帧、930个软件延迟关联样本、零重连；首帧239ms，软件延迟P95为315ms、最大375ms，最大输出间隔779ms，累计冻结5512ms（8.11%）。
这轮满足当前软件亚秒三项判据，但累计冻结仍未解决。此前四路取消模式10.84%、串行5.97%为不同运行样本，不能据此证明因果或稳定收益；候选继续默认关闭。
本轮没有调整码率、源画质、播放前导或正常读取150ms预算，也没有测量物理采集到屏幕的时延。
